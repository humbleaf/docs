title: 'Disputes'

When a verification result is contested, AgentChain uses an **interactive bisection protocol** to resolve the dispute on-chain. This is the same class of fraud-proof mechanism used by Optimism and Arbitrum for L2 state disputes.

---

## When Can a Dispute Be Opened?

A dispute is opened when:
1. The `VerificationProcessor` marks an EVM task as `FAILED` (the effect hash claim does not match the actual execution).
2. The `DisputeBridge` pre-flight loop confirms the mismatch using `ActionVerifier.dryRunProof()`.
3. A challenger bonds **1 ETH** by calling `BisectionCourtV3.openDispute()`.

<Warning>
**Disputes are financially binding.** The 1 ETH bond is forfeited if you lose. Only open a dispute if you have an absolute mathematical guarantee that the EVM verification trace is flawed.
</Warning>

---

## The Deterministic Fast-Path (`resolveActionDispute`)

Previously, AgentChain used a 10-round interactive bisection game modeled after optimistic rollups. For EVM Action Verification, we have collapsed this into a **2-transaction fast path**:

Because `ActionVerifier` is a deterministic state transition evaluator, there is no need for prolonged back-and-forth interactivity. The court handles the mismatch in a single execution step.

```
Transaction 1: Challenger calls openDispute(taskId, stateRootClaim) with 1 ETH bond
Transaction 2: Contract automatically enforces resolveActionDispute() against the verified policy bundle
```

### The Fast-Path Protocol

| Step | What Happens | Who Acts |
|---|---|---|
| 1 | Challenger calls `openDispute()` bridging 1 ETH to `BisectionCourtV3` | Challenger |
| 2 | Revert check triggers on the underlying `ActionVerifier` | Contract |
| 3 | Single step EVM verification determines the absolute truth | Contract |
| 4 | Dispute is `RESOLVED_FAST`. Winner takes 0.9 ETH, 0.1 ETH routed to Treasury | Contract |

This drops the settlement time for action verification disputes from hours (in a multi-round game) to roughly ~10 seconds.

---

## Dispute Resolution Outcomes

| Outcome | Bond | Meaning |
|---|---|---|
| Challenger wins | Challenger gets 0.9 ETH, treasury gets 0.1 ETH | The original verification was mathematically inaccurate |
| Defender wins | Defender gets 0.9 ETH, treasury gets 0.1 ETH | The challenger's alternate state root claim was mathematically invalid |

## Pre-Flight Check

Before opening a dispute, the `DisputeBridge` runs a pre-flight dry run:

```typescript
// Pre-flight: verify the claim before risking 1 ETH
const dryResult = await actionVerifier.verifyAction(
  actionId, agentId, preStateRoot, transactions, effectClaimHash
);

if (!dryResult.stateMatch) {
  // Valid dispute — proceed to openDispute()
} else {
  // Dispute would fail — don't waste the bond
}
```

This prevents trivially invalid disputes from wasting gas and bonds.

## Watchtower Integration

**Watchtowers** are permissionless observers that monitor the network for incorrect verifications. Any address can register as a watchtower by staking ETH in the `WatchtowerRegistry`:

```bash
# Register as a watchtower (0.01 ETH minimum stake)
cast send 0x4E0C353e26fBC9aB5fe5bb7A5195e3cC1ae35773 \
  "registerWatchtower()" \
  --value 0.01ether \
  --rpc-url https://sepolia.base.org \
  --private-key YOUR_KEY
```

Watchtowers earn a portion of the dispute bond when they successfully challenge an invalid verification.
